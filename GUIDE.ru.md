# Tutorly: пошаговый гайд (Arch Linux и AUR)

Что здесь есть: как влить изменения, проверить программу, поставить её пакетом так, чтобы она появилась в меню приложений, и при желании опубликовать пакет в AUR.

Что уже сделано в ветке `tutorly`:

- программа переименована в **Tutorly**, у неё новая иконка с книгой;
- убрана фиолетовая и синяя тема, дизайн строгий и минималистичный, есть светлая и тёмная темы (кнопка с луной или солнцем и выбор в настройках);
- добавлен пакет для Arch (`packaging/arch/PKGBUILD`), ярлык для меню и лаунчер.

Дальше по шагам. Шаги 1–4 нужны, чтобы программа стояла у тебя. Шаги 5–6 нужны только для AUR.

---

## Шаг 1. Влить изменения в `main`

Все правки лежат в одной ветке `tutorly` (в неё уже вошли `redesign-minimal` и `arch-package`).

**Через GitHub (проще всего):**

1. Открой https://github.com/razenfh/tutorly/pull/new/tutorly
2. Нажми **Create pull request**, просмотри изменения, затем **Merge pull request**.

**Или из терминала:**

```
git clone https://github.com/razenfh/tutorly.git     # если репозитория ещё нет локально
cd tutorly
git fetch origin
git checkout main
git merge origin/tutorly
git push origin main
```

Старые ветки `redesign-minimal` и `arch-package` после этого можно удалить, они полностью входят в `tutorly`.

> Важно: `PKGBUILD` собирает пакет из ветки `main`. Пока изменения не влиты, пакет соберётся из старого кода (без новой иконки и без темы).

## Шаг 2. Проверить программу без установки

Это быстрая проверка, что всё запускается.

```
sudo pacman -S --needed nodejs npm
cd tutorly
npm install
npm start
```

Что должно быть: окно «Tutorly», иконка луны или солнца в шапке переключает тему. Если в пустой программе нажать «Показать пример», появятся тестовые ученики и уроки.

Если Electron ругается на `chrome-sandbox`, запусти так: `npx electron . --no-sandbox`.

## Шаг 3. Собрать и установить пакет (появится в меню)

```
cd tutorly
git pull
cd packaging/arch
makepkg -si
```

`makepkg` сам скачает исходники с GitHub, соберёт пакет `tutorly-git` и установит его через `pacman` (`-s` доставит зависимость `electron`, `-i` установит готовый пакет). Тебя попросят пароль для `sudo`.

После установки:

- «Tutorly» появится в меню приложений в категории «Образование»;
- программу можно запустить командой `tutorly`;
- данные лежат в `~/.config/tutorly`.

**Если ты раньше пользовался «Журналом репетитора»:** при первом запуске папка `~/.config/zhurnal-repetitora` сама переименуется в `~/.config/tutorly`, уроки и ученики сохранятся. На всякий случай перед обновлением сделай копию: «Настройки → Сохранить копию данных».

**Хочешь проверить до слияния в `main`?** Открой `packaging/arch/PKGBUILD` и временно замени `#branch=main` на `#branch=tutorly`. После проверки верни обратно.

**Если ярлык или иконка не появились:**

1. Выйди из сессии и зайди снова (меню обновляется не у всех оболочек сразу).
2. Выполни `sudo gtk-update-icon-cache /usr/share/icons/hicolor` и `sudo update-desktop-database`.
3. Запусти `tutorly` из терминала и посмотри, нет ли ошибок.

**Свои флаги Electron** (например, для проблем с графикой) можно записать в `~/.config/tutorly-flags.conf`, по одному в строке, например `--disable-gpu`.

**Удалить программу:** `sudo pacman -R tutorly-git`. Папка с данными при этом не удаляется.

## Шаг 4. Выбрать лицензию

В репозитории нет файла `LICENSE`. Для личного использования это не мешает, а для AUR лучше определиться.

1. Выбери лицензию (если не уверен, обычно берут MIT: можно свободно использовать, нужно только оставить имя автора). Подробнее: https://choosealicense.com
2. Положи текст лицензии в файл `LICENSE` в корне репозитория и закоммить его в `main`.
3. В `packaging/arch/PKGBUILD` замени строку `license=('custom')` на, например, `license=('MIT')` и удали комментарий `TODO`.
4. Для MIT, BSD и подобных лицензий Arch требует класть текст лицензии в пакет. Добавь в конец функции `package()` такую строку:

```
  install -Dm644 LICENSE "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
```

Если лицензию выбирать пока не хочешь, пакет всё равно соберётся и установится у тебя локально. Для AUR вернись к этому шагу.

## Шаг 5. Подготовиться к AUR

1. **Аккаунт.** Зарегистрируйся на https://aur.archlinux.org (у тебя он уже есть).
2. **SSH-ключ.** Если ключа нет:
   ```
   ssh-keygen -t ed25519 -C "aur"
   cat ~/.ssh/id_ed25519.pub
   ```
   Скопируй вывод и вставь в профиле AUR: **My Account → SSH Public Key**.
3. **Имя пакета свободно?** Поиск: https://aur.archlinux.org/packages?K=tutorly . Если пакет `tutorly-git` уже занят кем-то другим, выбери другое имя (например `tutorly-app-git`) и поменяй `pkgname` в `PKGBUILD`.
4. **Проверка пакета.**
   ```
   sudo pacman -S --needed namcap
   cd packaging/arch
   makepkg
   namcap PKGBUILD tutorly-git-*.pkg.tar.zst
   ```
   Замечания про `electron` и зависимости можно смотреть по смыслу, критичны только настоящие ошибки.

## Шаг 6. Залить пакет в AUR

AUR принимает только ветку `master`, поэтому клонируем с таким именем ветки (настройка действует только на эту команду).

```
git -c init.defaultBranch=master clone ssh://aur@aur.archlinux.org/tutorly-git.git aur-tutorly-git
```

Git скажет, что клонируешь пустой репозиторий: так и должно быть.

```
cd aur-tutorly-git
cp ../tutorly/packaging/arch/PKGBUILD .
makepkg --printsrcinfo > .SRCINFO
git add PKGBUILD .SRCINFO
git commit -m "Initial import"
git push origin master
```

Если `git push` отвечает ошибкой про ветку, выполни `git push origin HEAD:master`.

Через минуту пакет появится на https://aur.archlinux.org/packages/tutorly-git .

**Заполнить автора.** В первой строке `PKGBUILD` стоит `# Maintainer: razenfh`. Можно заменить на `# Maintainer: Имя <почта>`.

**Обновления.** Для `-git`-пакетов не нужно выкладывать новую версию при каждом коммите: версия считается при сборке сама. Менять и заново пушить в AUR нужно только если ты правишь сам `PKGBUILD`, каждый раз заново генерируя `.SRCINFO`. Пользователи с `yay` обновляют такие пакеты командой `yay -Syu --devel`.

## Дополнительно: AppImage

Если нужен один исполняемый файл без установки:

```
sudo pacman -S --needed fuse2
npm install
npm run dist
```

Готовый файл появится в `dist/` (имя вида `Tutorly-0.1.0.AppImage`). Запуск: `chmod +x dist/*.AppImage && ./dist/*.AppImage`. В меню приложений AppImage сам не появляется, для этого и нужен пакет из шага 3.

## Что я не менял

- Сервер для совместной доски (`server/`): имена вроде `/opt/zhurnal-board`, пользователь `zhurnal` и сервис `zhurnal-board` остались прежними, чтобы не сломать уже развёрнутый сервер. На работу они не влияют. Поменялись только описания.
- Мобильное приложение переименовано в Tutorly (название, `slug`, идентификаторы `com.example.tutorly`). Перед публикацией в магазинах замени `com.example.tutorly` на свой идентификатор, как описано в `mobile/README.md`.

## Что я не проверял

Эта программа и пакет собирались в среде без Arch, поэтому реальные `makepkg`, запуск окна Electron и отображение ярлыка в твоей оболочке я не проверял. Проверено другое: установка файлов из `PKGBUILD` в тестовую папку, запуск лаунчера с подставным Electron, перенос данных из старой папки и отрисовка интерфейса и иконки в браузере. Если что-то пойдёт не так, начни с запуска `tutorly` из терминала и посмотри на вывод.

# Сервер журнала и совместной доски

Маленький сервер на Node.js. Он делает две вещи:

1. **Хранит ваш журнал** (ученики, уроки, оплаты, домашка) и синхронизирует его с программой. Для каждого ученика есть постоянная страница по ссылке: ученик и родители видят свои уроки, переносы с причинами и домашнее задание, а ещё могут отметить «сдал(а)». Программа остаётся рабочей и без сети, данные лежат и на компьютере, и на сервере.
2. **Даёт совместную доску**: ученик открывает доску урока по ссылке и вы рисуете вместе в реальном времени.

Программа репетитора подключается к серверу сама, ученикам ничего устанавливать не нужно.

## Аккаунты, роли и курсы

При первом запуске программы человек выбирает «я ученик», «я родитель» или «я учитель» и создаёт аккаунт: имя, логин и пароль, почта не нужна. Учитель заводит ученика, у ученика появляется «курс» (один ученик = один курс, как в Classroom) с двумя кодами: для ученика и для родителя. Ученик или родитель вводит код в своей программе и видит курс: уроки, переносы с причинами, домашку. Ученик может отметить «сдал(а)» и открыть доску урока, родитель только смотрит.

- Регистрация открыта для всех. Чтобы учителей могли создавать только свои, задайте `TEACHER_INVITE` в файле окружения.
- Данные каждого учителя лежат отдельно: `data/teachers/<id>/journal.json`; аккаунты в `data/accounts.json`; комнаты досок в `data/rooms/`.
- Забыли пароль: учитель сбрасывает пароль ученику и родителю в окне «Курс: коды и участники», а самому учителю пароль сбрасывает администратор:

```
ADMIN_TOKEN=ваш_ключ node admin.js list
ADMIN_TOKEN=ваш_ключ node admin.js reset логин
ADMIN_TOKEN=ваш_ключ node admin.js delete логин
```

Сброс выдаёт временный пароль и завершает все сессии аккаунта. `ADMIN_TOKEN` теперь только для этих команд, в программе его вводить не нужно.

## Как работает журнал

- Каждая запись (ученик, урок, задание) в программе помечена временем последнего изменения. Программа раз в минуту и после каждой правки обменивается изменениями с сервером. Если одну запись изменили в двух местах, побеждает более поздняя правка. Удаления тоже синхронизируются.
- Если у вас будет программа на нескольких устройствах (компьютер и потом телефон), они сойдутся через этот сервер. Часы на устройствах должны идти правильно.
- Страница ученика: в программе в карточке ученика кнопка «Живая ссылка». Ссылка вида `https://ваш-домен/s/<ключ>`, у каждого ученика своя. Можно переключить «Показывать оплату». Кнопка «Создать новую ссылку» отключает старую.
- Ученик и родители не видят заметки, цену, контакт и чужие данные: сервер отдаёт им только расписание, переносы, причины, темы и домашку. Оплата показывается только если вы включили.
- Файл журнала на сервере: `data/journal.json`. Его нужно включать в резервные копии вместе с `data/rooms`.

## Как работает доска

- Для каждого урока сервер создаёт комнату с двумя ключами: ваш (репетитора) и ученика. Ссылка для ученика вида `https://ваш-домен/r/<комната>?k=<ключ ученика>`.
- Всё, что рисуется, рассылается участникам сразу. Видны курсоры друг друга. Доска комнаты хранится на сервере в папке `data/rooms`, ваша копия остаётся и в локальном файле программы.
- Вы можете в любой момент запретить ученику рисовать (кнопка «Ученик рисует: да/нет»).
- Создавать комнаты и синхронизировать журнал можно только с ключом администратора (`ADMIN_TOKEN`). Он вписывается в настройках программы.

## Установка на VPS (Ubuntu или Debian)

Нужен домен, направленный на IP сервера. Без домена нельзя получить HTTPS, а без него ссылку лучше ученикам не отправлять.

1. Node.js не ниже 18. Проверьте `node -v`. Если нет: `sudo apt install nodejs npm` (или поставьте свежий Node по инструкции nodejs.org).
2. Скопируйте папку `server` на сервер в `/opt/zhurnal-board` (например `scp -r server user@сервер:/tmp/` и потом `sudo mv /tmp/server /opt/zhurnal-board`).
3. Установите зависимости и создайте пользователя:
   ```
   cd /opt/zhurnal-board
   sudo useradd --system --home /opt/zhurnal-board zhurnal
   sudo npm install --omit=dev
   sudo mkdir -p data && sudo chown -R zhurnal:zhurnal data
   ```
4. Ключ администратора:
   ```
   openssl rand -base64 24
   sudo cp .env.example /etc/zhurnal-board.env
   sudo nano /etc/zhurnal-board.env      # вставьте ключ в ADMIN_TOKEN
   sudo chmod 600 /etc/zhurnal-board.env
   ```
5. Автозапуск:
   ```
   sudo cp zhurnal-board.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now zhurnal-board
   sudo systemctl status zhurnal-board
   ```
6. HTTPS через Caddy:
   ```
   sudo apt install caddy
   sudo cp Caddyfile.example /etc/caddy/Caddyfile
   sudo nano /etc/caddy/Caddyfile        # впишите свой домен
   sudo systemctl reload caddy
   ```
   Откройте порты: `sudo ufw allow 22 && sudo ufw allow 80 && sudo ufw allow 443 && sudo ufw enable`. Порт 8080 наружу открывать не нужно.
7. Проверка: `https://ваш-домен/health` должен ответить `ok`.
8. В программе: Настройки, поле «Адрес сервера» (`https://ваш-домен`) и «Ключ администратора». Дальше в любой доске появится кнопка «Совместная доска». Она создаёт комнату, подключает вас и копирует ссылку для ученика.

## Обновление и копии

- Если вы меняли `renderer/board.js` или `renderer/live.js` в программе, на сервере нужно обновить страницу ученика: на компьютере в папке `server` выполните `npm run sync` и заново скопируйте папку `public` на сервер.
- Резервная копия: папка `/opt/zhurnal-board/data` (в ней `journal.json` и `rooms`). Её достаточно копировать целиком.
- Если сервер потерял данные или вы поставили новый, подключите программу к нему как обычно: она сама отправит на сервер всё, что есть на компьютере.
- Логи: `sudo journalctl -u zhurnal-board -f`.

## Что учесть

- Отмена (Ctrl+Z) отменяет только ваши действия и не удаляет то, что нарисовал другой участник.
- Порядок слоёв («наверх», «вниз») между участниками не синхронизируется.
- Если связь пропала, доска продолжает работать, а при возвращении связи ваши новые объекты отправятся на сервер. Удаления, сделанные без связи, на сервере не применятся.
- Ссылка ученика содержит его ключ. Тот, у кого она есть, видит доску. Если ссылка попала не туда, удалите урок или создайте комнату заново: у урока есть своя комната, при смене адреса сервера в настройках создаётся новая.
- Лимиты: до 20 участников в комнате, до 5000 объектов на доске, до 2000 комнат на сервере, до 20000 записей журнала.
- Защита страницы ученика: ключи длинные (перебрать нельзя), а частые неверные попытки с одного адреса блокируются на минуту. Для этого в `/etc/zhurnal-board.env` должна стоять строка `TRUST_PROXY=1` (она есть в `.env.example`).
- Сервер проверен тестами в среде разработки, но на настоящем VPS и в настоящем Electron вы запускаете его впервые. Если что-то не заработает, пришлите вывод `journalctl` и текст ошибки.
